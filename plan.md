# План: Приоритизация гипотез (ICE / RICE) внутри воронки

Файл: `ai_studio_code.html` (единый автономный HTML). Все правки вносятся в него.
Цель: закрыть цикл PM «нашёл падение → гипотеза → приоритизация → эффект на воронке».
Считаем сами: ICE = (Impact × Confidence × Ease) / 100; RICE = (Reach × Impact × Confidence) / Effort.
Главная фишка (V2): гипотеза привязывается к этапу воронки, Reach и эффект в деньгах считаются автоматически из текущей воронки.

---

## Модель данных

### 1.1. Состояние
- `hypotheses: []` — массив объектов гипотез.
- `state.scoreModel: 'ICE' | 'RICE'` — активная модель скоринга (по умолчанию `'ICE'`).

### 1.2. Объект гипотезы
```js
{
  id: number,            // Date.now()
  name: string,          // «Убрать шаг формы»
  stageIndex: number | -1, // индекс этапа воронки, -1 = не привязана
  boostPp: number,       // ожидаемый прирост CR этого этапа, п.п. (0..100)
  // ICE
  impactI: number,       // 1..10 (или auto, если привязана)
  confidenceI: number,   // 1..10
  easeI: number,         // 1..10
  // RICE — ручной ввод (если не привязана) либо auto
  reachR: number,        // юзеров за период
  impactR: number,       // 1..3
  confidenceR: number,   // 0..1 (доля)
  effortR: number,       // 1..10 (или человеко-недели)
}
```

### 1.3. Ключевой принцип V2 — «считать самим»
Если гипотеза привязана к этапу (`stageIndex >= 0`) и задан `boostPp`:
- **Reach (auto)** = количество пользователей текущей воронки, достигающих этапа `stageIndex` (берём `getStageValues()[stageIndex]`).
- **Impact** считается из эффекта на метрику:
  - новых оплат ≈ текущие оплаты × (1 + boostPp% к финальному CR) минус текущие (упрощённо: `sN × (boostPp / CR перехода)`) — точную формулу зафиксируем при реализации и покажем в тултипе;
  - прирост выручки ₽ = новые оплаты × AOV.
- Эти значения **автоподставляются в Reach и Impact** RICE-формулы, поля становятся readonly с пометкой «auto».
- Если PM не привязывает гипотезу — используются ручные `reachR` / `impactR` / `impactI`.

### 1.4. Совместимость с состоянием
- `hypotheses` включаем в `snapshotState` / `restoreSnapshot` / `saveToStorage` / `loadFromStorage` / `resetAll` / `saveScenario` / `snapshotCurrentPeriod` / `shareLink`.
- `scoreModel` добавляем в `DEFAULT_STATE`.

## Вычисления

### 2.1. Чистые функции
- `computeHypothesis(h, stageVals)` → `{ ice, rice, iceRaw, riceRaw, reach, impact, revenueBoost }`, где:
  - `ice = (impactI × confidenceI × easeI) / 100`;
  - `rice = (reach × impact × confidence) / effort`;
  - при привязке `reach`, `impact`, `revenueBoost` выводятся из `stageVals` и `boostPp` (auto), иначе из ручных полей.
- `sortHypotheses()` — по убыванию активной модели скоринга.
- `hypothesisStageValue(stageIndex)` — обёртка над `getStageValues()`.

### 2.2. Авторасчёт эффекта (показать формулу в тултипе)
- Текущий CR перехода к этапу: `cr_i` (stage-режим) или `% от трафика` (cumulative-режим).
- Новые оплаты ≈ `sN × (1 + boostPp / cr_i)` при `cr_i > 0` (линейная аппроксимация роста финальной конверсии).
- Прирост выручки = новые оплаты − текущие оплаты, × AOV.
- Формулу зафиксировать в коде как единую функцию (переиспользовать и в RICE, и в экспорте).

## Интерфейс

### 3.1. Секция «Приоритизация» (после «Маркетинговые метрики», перед шарингом/экспортом)
- Заголовок + переключатель модели **ICE / RICE**.
- Таблица строк-гипотез:
  | Гипотеза | Этап воронки | Метрика/эффект | Reach | Impact | Conf. | Ease/Effort | Скоринг (ICE/RICE) |
  |---|---|---|---|---|---|---|---|
- Кнопка «+ Гипотеза» (по аналогии с «+ Этап»), удаление строки, `stageIndex` — `<select>` со списком этапов воронки (+ «— не привязана —»).
- Поля компонентов — число или слайдер (стиль как у базовых метрик).
- **Автосортировка** по убыванию активной модели; топ-1 выделен рамкой, топ до 3 — подсветкой «⭐».
- При `stageIndex >= 0`: Reach и Impact/эффект — `readonly`, зелёная метка «auto», тултип с формулой расчёта.
- Подсказка-рекомендация: «Запустите первыми: <название>».

### 3.2. Переключение моделей
- Смена `scoreModel` не теряет данные (храним обе группы полей).
- Кнопка-переключатель — like display-mode toggle; при смене — `pushHistory()`, пересчёт, сортировка, `saveToStorage()`.

## Данные и сохранение

- `saveHypotheses()` / `loadHypotheses()` — через общий storage (внутри `saveToStorage`/`loadFromStorage`).
- Экспорт: добавить секцию «Гипотезы» в `exportPDF` (таблица + скоринг), строки в `exportCSV`, массив в `exportJSON`.

## Критерии приёмки (V1+V2)

1. Можно добавить гипотезу, привязать к этапу, задать `boostPp` → Reach/эффект в деньгах считаются автоматически из данных воронки и видны (с формулой в тултипе).
2. RICE и ICE считаются автоматически; переключение модели сортирует строки по убыванию и не теряет введённые данные.
3. Топ гипотеза выделена; рекомендация «запустить первыми» видна.
4. Гипотезы сохраняются после перезагрузки; попадают в CSV/JSON/PDF-экспорт.
5. При смене этапов/удалении этапа из воронки привязки гипотез не ломаются (индекс клампится/сбрасывается в `-1`).
